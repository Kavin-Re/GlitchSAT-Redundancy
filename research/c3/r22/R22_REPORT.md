## 0. Short answer (review-ready)
- Real glitches are not "one clean flipped wire". Global methods (voltage, clock) hit many wires at once; EM is local but does not target a single bit; laser is the most precise and can give single-bit faults on small targets. Laser/EM faults on storage cells are often described as set/reset (a bit goes to 0 or to 1) rather than flip. No source I found gives a universal "N nets per event" number.
- The countermeasure-verification tools I found (SYNFI, FIRMER) count a fault as one gate (output) event, once per gate. That is the same as our "one stem flip = 1 fault" rule. I found no paper that argues stem versus branch as a security modelling choice. UNVERIFIED (absence of hits only).
- So our rule has precedent in the security tools and is physically consistent with "a transient on a gate output reaches every fanout", but no source says it is "the right" rule. Honest statement: it is the convention of the field, and it corresponds to a driver-node upset; it is not a measured property of any specific attack.

## 2. Fault models adopted by verification papers (question 2)
- FIRMER: a fault is a gate event, at most once per gate, counted per gate, no stem/branch distinction. SOURCED via R23 (R23_REPORT.md section 1; https://arxiv.org/html/2307.00561v1, TCHES 2024 issue 4). Justification text not re-read by me.
- SYNFI (Nasahl et al., TCHES 2022, https://bmt.ub.rub.de/index.php/TCHES/article/view/9813 ; arXiv 2205.04775): injects single and multiple faults into extracted synthesized sub-circuits, gate-level (replacing gate function). SNIPPET for the fault list; R10 read the full text. I could not retrieve its justification wording this round. UNVERIFIED.
- Richter-Brockmann, Sasdrich, Gueneysu, "Revisiting Fault Adversary Models - Hardware Faults in Theory and Practice", IEEE Trans. Computers 72(2) 2023 (ePrint 2021/296, https://eprint.iacr.org/2021/296). SOURCED (abstract): custom adversary models used for countermeasure validation "are often not tightly coupled with the actual physical behavior of available fault injection mechanisms"; they propose a consolidated adversary model tailorable to real mechanisms (clock glitch, voltage glitch, EMFI, laser listed) and integrate it into VerFI. This is the most direct published support for the point our FP report raised: abstract fault models in verification are conventions. The model's definitions I could not read (PDF not obtained).
- Set/reset versus flip: the physical literature above (Roscian 2013, Ordas 2017, Moro 2013) says set/reset or set-at-1 is closer to reality on storage and bus cells than a symmetric flip. SNIPPET/SOURCED as stated. Consequence: our XOR flip is a worst-case, superset-ish abstraction, since a flip equals a set when the value is 0 and a reset when it is 1; the converse is not true (a set cannot flip a 1). UNVERIFIED as a general statement but it follows from the definitions.
- Justifications offered: from the sources I saw, mainly "a bit-flip for one cycle is the common abstraction" (survey snippet: for most techniques the fault can be modelled as a bit-flip, transient, one clock cycle; SNIPPET) and tool convenience. I found no source that derives the abstraction from physics for gate nets.

## 3. Stem versus branch as a physical choice (question 3)
- Classical test: stem and branch faults are distinct; a net with fanout to k gates has k+1 stuck-at locations (one stem, k branches), and the single stuck-at model assumes branches are independent. SNIPPET: NPTEL lecture notes 106103016, module 7, lecture 2 (archive.nptel.ac.in) ; R23 section 2 lists lecture notes (UNM, TU Delft, Utah) saying the same. SOURCED as lecture material, not a primary paper.
- Physical reading (my reasoning, UNVERIFIED as published): a transient that disturbs the driver cell's output node is seen by all receivers on that net, so it is a stem fault. A transient or defect on a metal segment past a fanout split is seen only by the receivers beyond the split, so it is a branch fault. Radiation/laser charge collected at a driver node gives a stem-like SET (Bagbaba 2020 treats SET at a gate output as reaching the fan-out cone). A branch-only event needs a local disturbance on a wire segment or at the receiver input; EM coupling onto a long wire is a possible mechanism but I found no measurement of it. UNVERIFIED.
- No paper found that treats the counting convention as a variable in a security min-fault question (R23 reached the same conclusion). UNVERIFIED (absence of hits).
- A subtlety to keep honest: even the stem=1 rule is one event but that event may have a large logical effect (all fanouts flip). The "cost = fanout" rule charges a stem event as f faults; it has no physical support I found (a single node upset does not cost more because more gates read it). It is better read as a robustness stress: "what if the attacker needs to perturb each receiver separately".

## 4. Recommendation (question 4)
1. Primary rule: count one gate-output (or flop-Q) flip as ONE fault, i.e. the stem rule, as FIRMER does. Physical statement that can honestly be made: "this corresponds to one transient disturbance at one driver node, which then reaches every gate that reads that node. It matches the gate-level SET abstraction used for laser/radiation (Bagbaba 2020) and the per-gate counting of FIRMER. It is a modelling convention shared with the security-verification tools, not a measured property of a specific glitch."
2. Report the branch-only rule as a second, finer-grained lower bound on what a very local attacker could do (a fault on a single receiver pin). It can only make the attacker's options larger or equal in the sense of more sites, so the minimum found under it can be equal or lower than under the stem rule when branch flips are cheaper to exploit; the project data (B1: V1 goes 1 to 2 under some models, V2 stays 3) should be re-read in that light. Do not claim which direction without checking per case.
3. Treat "cost = fanout" as a stress test, not as the physical rule. Say plainly that it is not supported by any source found.
4. Add a correlated/global row (one event flips a cone or neighbourhood) because voltage and clock glitches are global per the SoK, and Moro's EM result shows one event setting about 9 to 10 bus bits. B1 already shows this breaks spike V2 with 1 event; this is the physically best-supported caution against reading "V2 needs 3" as an attack-cost statement.
5. Consider set/reset variants (fault forces 0 or 1 instead of XOR) as a sensitivity row, because the storage-cell literature says set/reset is the observed behaviour. Not done in the project; suggested only.
6. Never say the rule is "physically right". Say: "several rules are defensible, the verdict depends on which is used, I report all, and the stem rule is my headline because it is the field's convention."

## 5. Plain-words answer to "why did you count a fault this way?"
"I counted one flipped gate output as one fault, however many gates read that output. The reason is that a short disturbance at a gate's output reaches everything connected to it, and the published formal tools for this problem, for example FIRMER, also count one fault per gate. It is a convention, not something I measured. Real glitches differ: voltage and clock glitches hit many places at once, EM can set many bits of a bus in one pulse, and laser on memory cells looks more like set-or-reset than a flip. So I also report other counting rules and a group-flip case, and I say that the number of flips is a worst-case modelling bound, not a cost to a real attacker."
