## What was built (the DA3 A3 gap: "synthesis build/flags and counting rule are not in the product")
1. **Counting rules** `--count-rule stem | fanout | fanout_pins | fanout_gates` (config key `faults.count_rule`; `fanout` = `fanout_pins`, recorded under that name; `branch` still exit 3 "NOT IMPLEMENTED").
   - Rule definitions are those of `research/c3/rep` and `docs/edu/tools/edu_scope.py`: cost of flipping a net = number of gate input pins (a repeated pin counts twice) + flop D pins (+ output-port bits for `fanout_pins` only), at least 1. `max_flips` becomes a COST budget. Engine: `_engine.net_weights()`; a flip of weight w is w items in the existing sequential counter (no new solver); flips heavier than the budget are excluded.
   - The scope block states the rule (`scope.options.count_rule`, `scope.fault_model`, the text `scope:` lines, `scope_line`). Report additions only: `min_cost`, per-fault `cost` (only for fanout rules); stem reports have no new keys (tested). Exit codes 0-4 and `faultbound-wt-report/1` keys unchanged.
   - `--scope-sweep --sweep-count-rules stem,fanout_pins,fanout_gates` adds the rule as a third axis (columns `... rule=...`; cells and columns carry `count_rule`; CSV gets a trailing `count_rule` column; without the flag the table is as before).
2. **`--synth-sweep`** (Verilog + `--top`; yosys needed, else exit 3 with a message; JSON input exit 3). New module `synth_sweep.py`. Built-in variants: `plain` (scripts/synth.sh plain), `plain_opt_merge`, `flatten_before_abc`, `abc_fast`, `abc_no_mux`, `opt_flow` (synth + dffunmap), `plain_keep_off`, `opt_flow_keep_off` (strips `(* keep *)`, keeps keep_hierarchy). Script template is documented (QUICKSTART 4c) and stored in the JSON result; run as `yosys -q -s flow.ys` in a private dir with the source as `design.v` (script file, because newer Yosys splits `-p` on commas). Output per variant: netlist sha256, gates, flops, min flips (per-cell timeout => `unknown`; `unsupported` / `synth-failed` rows are explicit), Yosys version in the header, then `verdict changes across N variants: min flips ranged a..b (at max_flips=k: ATTACK_FOUND in x, NO_ATTACK_UP_TO_BOUND in y ...)`. Byte-identical netlists are analysed once (marked `*`). `--synth-variants FILE` (.toml `[[variant]]` or .json) adds custom flows (fields name, description, extends, pre, abc, post, strip_keep); `--synth-select`, `--sweep-out .json/.csv`, `--timeout-s` (hard kill, exit 2) work. Custom flows: deny-list for shell/plugin/script/exec/tee/write_*/extra reads/`!` (a deny-list, not a sandbox; documented).
3. Docs: QUICKSTART 4c, README line, `product/examples/synth_sweep/` (v2.v, variants.toml, expected_output.txt), `examples/scope_sweep/scope.toml` comment updated. Tests: `product/tests/test_ps6.py` (35 tests; Yosys-dependent ones skip without yosys: 18 passed / 17 skipped with PATH stripped, MEASURED).

## Limits / not done (honest)
- `branch` counting (partial-branch flips) is not implemented; the REP 32/32 figure does not cover it either.
- The synth sweep samples 8 built-in flows plus custom ones; it is not the E2 864-configuration matrix (no multiple ABC scripts beyond fast/no-MUX, no `-dff`, no `abc` omitted, no second Yosys build). Only apt Yosys 0.33 was available; the 0.33 vs 0.38 difference E2 found (V2 baseline 2 vs 3 flips) is therefore NOT reproduced here.
- Netlist hashes in `--synth-sweep` come from this flow (source read as `design.v`), so they differ from the hash `analyze rtl/v2.v` or REP's scripts give for "the same" flow (REP baseline sha16 f954078f..., sweep `plain` f3fe9621...). Compare hashes within one tool and Yosys version only. Gate counts and min flips agree.
- Single-file Verilog only for the sweep (`include files are not copied). Custom-flow command filtering is a deny-list, not a sandbox.
- Under a fanout rule the `explanation` text still counts "flips" (nets); the cost is appended as a sentence. Per-cycle attacker input is not covered (existing TODO).
- The counting rule changes the answer on only some cells (spike V2 word: not at all; inputs as sites: 1 -> 3). That the rule is physically meaningful is not claimed (REP/BC row 3 objection stays open). Nothing here is established as new.
- Existing sweep-code is still a nested loop around `analyze()`; the new axes add loops of the same kind plus the new weighted counter and the flow generator. Not claimed as more.
- GitHub Action/CI examples not re-run. RT2 red-team interplay: no exit code, schema key or option semantics changed (additions only; 139 pre-existing tests unchanged and passing).
