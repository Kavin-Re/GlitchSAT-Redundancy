Kept on purpose: `results/` (including `results/work`): `ci/check_reproduce.py` reads `results/reproduce_summary.json` and `results/reproduce/*.json`, and docs cite them.
The build fails (exit 3, nothing written) if a text file in the staging set matches the secret/PII scan in the allow-list file (any email except the listed benign tool/placeholder ones, linkedin, API-key shapes, private keys, bearer tokens). The owner's name and email are not in the allow-list; to catch them, add a local `[PII]` line (do not commit it). The scan reads text files only: binaries (pptx, png, pdf) are not scanned. The pptx metadata is the python-pptx template default (no owner name; checked once by hand).

## How to verify
1. `scripts/make_bundle.sh` (dry run): counts, 20 largest files, .md count, exclusions, scan result.
2. `scripts/make_bundle.sh --build`: writes `project_viva_kit_<UTC>.zip`, `project_full_tree_<UTC>.zip`, `SHA256SUMS` (check with `sha256sum -c SHA256SUMS`). Zip entries carry a fixed 2026-01-01 time and sorted order, so the same tree gives the same bytes for the same file set; the name carries the build time (`BUNDLE_TS` overrides it).
3. `scripts/verify_bundle.sh`: unzips B to `/tmp/bundle_verify/`, creates a venv `/tmp/bundle_verify_venv`, and runs `pip install ./product[test]`, `check_reproduce.py` and `--rerun`, `pytest tests`, `pytest product/tests`, `scripts/check_numbers.py`, the three START.md commands (inside the unzipped copy), `dashboard/build.py` (index.html hash must not change), and a forbidden-path check; lists files with `/tmp` or `/home/user` in `/tmp/bundle_verify_paths.txt`. Needs yosys and iverilog on PATH and pypi.org. About 5 minutes. Log: `/tmp/bundle_verify_log.txt`.

## What does not re-run
Research scripts under `research/` (about 340 files mention `/tmp` or `/home/user`; list in `research/c5/bundle/hardcoded_paths.txt`) are evidence, not a pipeline: they were run on scratch copies and read inputs from `/tmp/work_*`. Where an inputs folder exists, a `RUN.md` says how (`research/c4/b3_inputs/RUN.md`, `research/c4/l2_inputs/RUN.md`). Layout and formal flows need micromamba, OpenROAD, sky130 and other tools not in the bundle (`scripts/setup_layout_tools.sh` hard-codes `/tmp/mm_root`). `START.md` tells the reader to `cp -r /home/user/project /tmp/proj_copy`; inside the bundle use the unzipped folder instead. Not hard-coded in the run path: `make test/reproduce/check-reproduce/replay/dashboard`, `scripts/glitchsat.py`, `product/` (the only hits there are two test files that mention paths in strings; their tests pass).
