# Counting conventions of related fault-verification tools

Uses only what `research/c4/sweeps/SWEEP_S1.md`, `SWEEP_S2.md` and `research/c3/r23/R23_REPORT.md` SOURCED rows say; everything else is UNVERIFIED. Nothing here is a claim of novelty.

| Tool | Evidence style (sampled vs bound) | Counting unit (per gate vs per stem) | Label |
|---|---|---|---|
| VerFI (2019/2020) | Simulation: user sets adversary bounds and test vectors, so sampled over the vectors given | Not stated on pages read; per fault kind, cycle and cell in the report | SOURCED (thin); unit UNVERIFIED |
| VERICA (TCHES 2022) | Verification of a Verilog netlist against a bound on simultaneous faults (`number`); exhaustiveness not checked here | Bound is max simultaneous faults by location class; stem or branch rule not shown | SOURCED; stem vs gate UNVERIFIED |
| FIRMER (arXiv 2307.00561) | Bound: SAT encoding, upper bounds `ne`, `nc` per vector; fault-resistant if every allowed vector is ineffective | Per gate, with a split budget: each gate faulted at most once per vector (R23); the budget is zeta(ne, nc, T, l): at most `ne` events per cycle, at most `nc` cycles containing faults, allowed fault types, gate class (c, r, cr) (S3, from the arXiv HTML) | SOURCED (partial; last third of the HTML unread) |
| SYNFI (arXiv 2205.04775) | Enumerates fault sets on the synthesized netlist with SAT (does not search a minimum); user sets count, location, effect | Per gate, or per state-register bit for FSM experiments. SYNFI has no unrolled cycles: pipeline registers become pass-through and loops are broken, so its numbers are not comparable with a T=6 unrolling without a caveat (S3) | SOURCED |
| FIVER (ePrint 2021/936) | Symbolic (BDD) injection, exhaustive within its model | Not stated on the abstract page; a gate-based unit would be an inference from SYNFI | SOURCED (abstract); unit UNVERIFIED |
| uArchiFI (CEA-LIST; Tollec et al. 2023) | Bounded model checking (yosys-smtbmc or Pono); UNSAT at a bound means robust only up to that step | Fault model (L, T, E): registers or signals (not gates), a bounded cycle window, effects set/reset/flip. One total budget N (`-cnt N`) over the bounded window. The README does not say whether a multi-fanout signal counts once | SOURCED (S3); fanout rule UNVERIFIED |
| k-FRP (Tollec et al., TCHES 2024(4), ePrint 2024/247) | Inductive invariant: proves at gate level that up to k faults are caught, independent of the program (as described in a search snippet) | Fault unit, counting rule for k and cycle model: UNVERIFIED (paper not read; identification is SNIPPET only) | SNIPPET; units UNVERIFIED |
| This project | Bound: z3 UNSAT within T cycles and at most k flips (headline T=6, k<=3); `>3` means no attack found up to 3, not secure | Headline: one flipped net (stem) = 1 fault, however many gates read it; fanout counting (net = f faults) is a stress test; neither rule shown physical | MEASURED |

Why this matters: the same design gives 2 flips under stem counting on 26 of 32 rebuilt netlists and 3 on all 32 under fanout counting (`research/c3/rep/REP_REPORT.md`), so a "minimum faults" figure is only comparable between tools when the counting unit matches.

Synthesis dependence was previously shown by SYNFI: faults needed dropped 3->2 after Yosys FSM recoding and 4->2 after register merging; `set_dont_touch` restored 4. Our E2 replicates the effect on a toy design across 864 synthesis configurations and a keep-attribute axis.

## S3 additions (agent DOCS-FINAL from `research/c4/sweeps/SWEEP_S3.md`, 2026-11-20)
- FIRMER counts per gate with a split budget (`ne` events per cycle, `nc` cycles with faults, plus gate class); our budget is one total k <= 3 over T = 6, so "k" is not the same quantity.
- SYNFI has no unrolled cycles (time-independent model); uArchiFI has one total budget N over a bounded window, on registers or signals; the k-FRP and FIVER counting units and cycle models are UNVERIFIED (k-FRP identification is a search snippet, FIVER abstract only). Do not write that any of them uses a given unit. RUN2 (measured) observed that uArchiFI counts per Yosys wire (a multi-fanout net costs 1), supports set/reset/flip/diff/xor (only flip run), and with one RTL wire as its unit gives 1 for V0, V1 and V2 alike; k-FRP asks about any output corruption with no alert, with no chosen goal value; FIVER was not run.
- **Dependent-failure vocabulary (secondary sources only; numbers paywalled, UNVERIFIED).** Safety standards (ISO 26262 as quoted by exida; IEC 61508-6 Annex D beta-factor method, checklist values not seen) call a failure that defeats redundancy a *dependent failure*: either a common cause failure (CCF: one root cause hits several elements) or a cascading failure. A dependent-failure analysis lists dependent failure initiators (DFI) and coupling factors (shared power or clock networks, shared resources). In that vocabulary our shared decision net `ok` is a coupling factor and a flip of it is a DFI/CCF; redundancy earns no credit against it. This is a naming aid only: it adds no result, and we computed no beta factor.
