What to ask a supplier

  1. Where do the redundant copies meet? Copies that end in one shared point count as one. Good answer: they name the exact place and show the copies stay separate until there, or that place is protected on its own.
    Worrying answer: “it is redundant” with no place named.
  2. How do you count a fault? A flip on a wire that feeds many places: one fault or many? Good answer: they say which, and can show results under both ways of counting.
    Worrying answer: one number, and no word on how it was counted.
  3. What is checked at the end? The finished wiring, not only the plan, and which output. Good answer: they name the finished wiring and the outputs checked, including any “accepted” light.
    Worrying answer: only the design plan was checked, or only one output.

What we did, and where it holds

A small model, checked on a computer. Nothing physical. No real product was tested or shown weak.

  • We only asked whether the lock’s main answer (the 8 lights) can be forced (see the caveat in the green box).
  • We assumed we know what the lock looks like when it is first switched on. Change any one of these assumptions and the 2-or-3 result stops applying:
  • We did not let the attacker change the code going in. Only wires inside the lock can flip.
  • Direction of the glitch. A power dip makes outputs fall (1 to 0). A push the other way (0 to 1) breaks even the guarded designs in our model. Which is realistic depends on the attack; we did not decide that.
  • Up to 3 flips tried. “3” means 3 worked and 2 did not. Nothing is said about 4 or more.

Sources and caveats

  • Sources: results/reproduce_summary.json, results/reproduce/*.json, docs/ENGINE_STATUS.md. Recheck with python3 docs/wow/check_game_answers.py.
  • The 2-flip attack on the apt 0.33 netlist is two gates, at cycle 0, that each feed several result-word bits (shared logic from ABC). The picture draws this as two joined wires: that is an ILLUSTRATION. No cited result says the two wires cover all 8 lights (research/c2/b2_scope reports only the minimum 2; research/c3/m1 has RTL and a script, no per-bit result), so which bits are covered is UNVERIFIED.
  • Counting rule: each flip counts as one regardless of fanout. 32 re-synthesized V2 netlists (2 Yosys builds x 2 flows x 8 ABC settings): 26 needed 2 flips and 6 needed 3 (MEASURED by agent DA, research/c2/devils_advocate/DA_CYCLE1.md; re-run by agent REP from the same recipe list, 64 of 64 rows agree, research/c3/rep/REP_REPORT.md; the 32 are one recipe, not independent designs). If a net costs one flip per gate input, flop input and output bit it feeds (per pin), all 32 need 3. When a wire shared by several pins counts once, 26 of 32 need 2. Toy 8-bit designs, 6 cycles, up to 3 flips. Flips of only some branches of a wire were NOT tested. Neither rule is shown to be physical. REP shared the recipe list with DA, so it is not fully independent. Not found in the sources we read: any check of which counting matches real hardware.
  • Goal is the 8-bit result word only: with the accept flag boot_ok as goal, V2 falls to 1 flip (CT-1, docs/dossier/CRITIQUE.md). Start state known, input nets not fault sites (a time-varying input check on the stored netlist only: research/c2/e1_timevarying).
  • Synthesis dependence was previously shown by SYNFI (faults needed dropped 3 to 2 after FSM recoding and 4 to 2 after register merging; set_dont_touch restored 4); our E2 replicates the effect on a toy design across 864 synthesis configs and a keep-attribute axis. Supply-dip rows (SIMULATED basis): under B3's 1-to-0-only rail model V1, V2 and V5 survive within the bound (V0 does not under a cone event), but a 0->1 event on the three compare copies breaks V2 and V5 with one event (V1 and V0 too): survival depends on polarity, not on triplication; SPICE supports 1-to-0 for supply dips, EM literature reportedly describes set-to-1 (UNVERIFIED, snippet level); the domain is the netlist hierarchy, not a physical rail; physical track closed (no extraction, selectivity unproven; L2 spread layouts failed LVS 4/4 by a known filler flow bug); a selective event costs 1. E2 split: 180/60/24 of 264 solved configs (152 distinct netlists: 94/38/20).
  • Conda 0.38+92 was not run for the opt flow. Real netlists have 58 to 85 gates; the pictures show only the wires that matter.
  • No hardware, no physical glitching: faults are modelled bit flips. Not yet tested by real people. No tracking, works offline. Working title TBD; licence undecided.
