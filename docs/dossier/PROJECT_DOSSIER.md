## 1. Problem statement
Plain: a chip checks a key before it boots. An attacker who disturbs one wire for one clock tick may trick it into booting with the wrong key. Designers add copies of the check. Do the copies help, and how sure can one be of "yes"? [`docs/report/PROJECT_REPORT.md` s1]
Technical: given a gate-level netlist (Yosys JSON) of a boot FSM, find the minimum number K of single-cycle bit flips (gate output or flop Q, any cycle among T) such that `boot_word == 0x96` while the attacker input `sig` differs from key `0xC3`. The baseline holds `sig` constant; E1 and B2 also run fresh input each cycle [`scripts/glitchsat.py` docstring; `docs/ENGINE_STATUS.md` "Model"].

## 4. Threat model and what a PASS means (details: `THREAT_MODEL_ONE_PAGE.md`)
Attacker: omniscient and worst-case; picks cycle and wire (symbolically, all at once) and `sig`; at most K flips in total. A fault flips the output net of a gate or a flop Q for one cycle; a flop-Q flip is transient on the output and what reads it, it does not overwrite stored state (`formal/FORMAL.md` s2). A PASS ("NO_ATTACK_UP_TO_BOUND") means: on THAT netlist file, in THAT fault model, for THAT goal and input treatment, no set of at most K flips within T cycles reaches the goal. It does not mean the Verilog, another netlist, a physical glitch, more flips or another goal is safe. A FAIL is a concrete witness replayed in an iverilog bench.

## 5. Method: SAT/BMC encoding from first principles
A circuit is a yes/no formula. Each gate gives `out = f(inputs)`; a fault gives each gate output a free switch `flip`, so `out = f(inputs) XOR flip`; time is unrolled T copies (bounded model checking); the goal clause says `boot_word == 0x96` in some copy with `sig != key`; the budget "at most K switches on" is a cardinality constraint; z3 answers SAT (witness) or UNSAT (none within the bound); the minimum is found by tightening K [`scripts/glitchsat.py` `build`, `solve`].
Hand-worked 3-gate example (ILLUSTRATIVE design; result MEASURED by `docs/dossier/worked_example.py`, D1 run): g1 = a AND b, g2 = a AND b, g3 = g1 AND g2; key a=b=1; goal g3=1 with (a,b) != (1,1). k=0 is UNSAT; k=1 is SAT by flipping the shared wire g3 with a=0; brute force over 3 input pairs x 8 flip patterns agrees (min 1; every 1-flip attack uses g3). This is V1 in miniature. Copies that end in the same wire share one point of failure; that follows from logic, not from the tool (FP s1.5).

### 7.2 Consumer-mask rule (M1). MEASURED, `research/c3/m1/M1_REPORT.md`
The '3' for V2 measures how wide the consumer's decoder is. All 255 bit-masks of the result word were solved for 5 designs (1785 cells, 0 unknown; T=6, k<=3), validated against a z3-free brute force at T=4, k<=2 on V2 spike (255/255 masks agree). The consumer-mask rule is the minimum of Hamming distance to idle states and the number of comparator copies touched: known-style cut/Hamming reasoning, not a discovery; exact on spike V2 (255/255), 187/255 on apt (DA3). Of 228 non-colliding masks (27 collide: legitimate states already match, cost 0), V2 spike needs 1 flip for 88 (39%), 2 for most of the rest and 3 for 44 (19%); only masks needing bits from all three comparator copies reach 3.
Headline table for the front page: full-word consumer 3 (spike) / 2 (apt 0.33); 4-bit consumer 1 to 3, typically 1 to 2 (of 68 non-colliding 4-bit masks: 28 need 1, 36 need 2, 4 need 3); single-net accept flag `boot_ok` 1; accept flag from V1: 1 for every mask.
Rule: min flips = min( over idle states s in {F0,CC}: popcount((s xor 0x96) & mask) , over subsets S of copies: |S| + popcount(~bits(S) & mask) ). It matches the solver on all 255 V2-spike masks (0 mismatches); it does NOT hold on the re-synthesised netlist (68 mismatches: ABC created shared nodes). Voting did not help: V2m (per-bit 2-of-3 vote) gives 2 for the full word and 2 for every mask of 6+ bits; V2s (one shared voter) gives 1 for every non-colliding mask. Voting only helps together with a hardened voter or a consumer that does not trust one net (M1 s5; fix direction is INFERRED, not built). Figure: `research/c3/m1/m1_flips_vs_mask.png`. DA2 (`research/c3/da2/DA2_REPORT.md` C1) found the same effect independently for masks of 1 to 4 bits.

| model | spike V0 | V1 | V2 | apt033 V2 | conda038 V2 |
|---|---|---|---|---|---|

Reading: correlated and input models give V2 1 to 2; set/reset/branch models keep V2 at 3 (V1 rises to 2); hold models give no attack up to 3. Caveat: the input-flip row partly reflects the spec issue (a flipped `sig` bit can look like the key), not a hardware weakness. The cone/neighbourhood rows are generous by construction. Groups come from the netlist graph, not from a layout. Validation: independent checker `modelsim.py` agrees on 36 of 36 (design, model) rows at T=4, but on V2 only 2 of 17 models were validated (the run was stopped). Not covered: the model semantics are modelling choices, none calibrated to a layout, supply network or clock tree; clock and reset are never fault sites.
Counting rule (R22, `research/c3/r22/R22_REPORT.md`; SOURCED by that agent from search results and 6 page fetches, no full paper read; D2 opened none): real glitches are not clean single-wire flips (voltage and clock glitches are global; EM is local but does not target one bit; laser can give single-bit faults; set/reset is closer to observed behaviour on storage cells than a symmetric flip). The verification tools found (FIRMER, SYNFI) count one fault per gate event, which is our stem=1 rule. No source argues stem versus branch as a security modelling choice (absence of hits only: UNVERIFIED). Recommendation, to say as written:
1. Headline: stem = 1 (one gate-output or flop-Q flip is one fault, however many gates read it). It matches a driver-node upset and the per-gate counting of FIRMER. It is the field's convention, not a measured property of any glitch.
2. Report the branch rule (each fanout pin separately) as a finer-grained second rule for a very local attacker; do not claim which direction it moves a given verdict without checking per case.
3. Fanout-weighted cost ("a flip of a net costs its fanout") is a STRESS TEST only. No source supports it as a physical rule.
4. Add a correlated/global row (cone or neighbourhood flip). Moro et al. (as cited by R22) saw one EM pulse set about 9 to 10 bits of a bus word on one microcontroller.
5. Add set/reset variants as a sensitivity row (B1 has set_only, reset_only).
6. NEVER say a rule is "physically right". Say: several rules are defensible, the verdict depends on which is used, I report all, and stem=1 is my headline because it is the field's convention.

### 7.8 Circuit-level link (EL1 SPICE). SIMULATED, `research/c2/el1_spice/EL1_REPORT.md`, `fault_windows.json`, `plot_A_supply_dip.png`, `plot_B_clock_runt.png`, `plot_C_setup_hold.png`

- A, supply dip on one shared rail (60 points: floors 1.0 to 0 V, widths 0.3/1/3 ns): flop Q held in ALL 60 points, even a 0 V floor for 3 ns. ## 16. For a reader from another field (plain words)
Think of a safe with a lock. A thief cannot get the key, but can hit the lock with a tiny well-timed shock so it opens with the wrong key. This project is a computer model of that, for the lock inside a chip that decides whether to start up. Engineers build two or three copies of the key check. You might think the thief must now beat every copy. Not always: if all the copies send their answer into one wire, a shock on that wire beats them all. We also found that whether the three-copy version looks safe depends on small choices that sound technical but matter: which signal the attacker is trying to change (the detailed result word or the final yes/no flag), whether the attacker may disturb the input wires, how the lock powers up, which program turned the design into a circuit, and how you count one "shock". Change one choice and the answer can go from "needs three shocks" to "needs one". So the lesson is not "three copies are good" or "bad"; it is that a statement like "resists two shocks" means nothing unless it lists its choices, and we built a small tool that reruns the question under each choice. What this does NOT show: that any real chip fails this way, that any real product is unsafe or safe, or anything about real electrical glitches. A "shock" here is a flipped 0 or 1 in a model.
