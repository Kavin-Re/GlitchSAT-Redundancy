# tools/harden: auto-harden for GlitchSAT

**Landing dependency:** the netlist-level fixes ("remove single points") and their tests use `merge_lint.py` and the
`surface` test fixture from `tools/surface/scripts` (override with `GLITCHSAT_SURFACE`). Land `tools/surface` together with
this module; without it those tests are skipped and `harden netlist` cannot run the merge lint.

## In plain words

GlitchSAT asks: "how many bit flips does an attacker need to make the toy boot check accept a wrong key?"
`glitchsat harden` answers the next question: "what is the cheapest change that makes that number at least G?"

You give a design and a goal G. The tool tries known countermeasures, one kind at a time and then in combination,
from cheapest to most expensive:

| countermeasure | what it means |
|---|---|
| state encoding | pick other code words for the idle / armed states (the manual 0xCC -> 0xA5 fix of `rtl/v2e.v`, searched over all values) |
| bit-to-copy ownership | change which compare copy drives which state bit |
| voter placement | remove the single voter net in front of the state register (one kept voter per bit, or no voter: each bit owned by one copy) |
| more copies | add compare copies that own state bits |
| alarm | a check copy whose disagreement forces reject; optional sticky alarm flop (a one-bit saturating alarm counter) |
| invalid state -> reject | states outside the four code words fall into reject |
| sparse state word | replace a 2-bit state + decoder (V0) by an 8-bit state word (as V1/V2) |
| keep copies separate | Yosys script that maps each copy on its own and marks its cells `keep` before flatten |
| remove single points | on an existing netlist: duplicate every gate the merge lint (`tools/surface/scripts/merge_lint.py`) finds shared between copies |
| consumer checks | the block reading `boot_word` must compare every owned bit |

Each candidate is checked by brute force: every wrong input, every set of up to G-1 flips, any number of clock
cycles, on three different gate mappings of the candidate. A candidate is accepted only if no attack exists on any of
them, the right key still boots, and the fault-free behaviour equals the description for all 256 inputs. Then you get
hardened Verilog, a Yosys script that keeps the copies apart, the cost, and a JSON file for the Studio "Suggest a fix"
panel.

What it is not: a security proof. Faults are modelled one-cycle bit flips of gate and flop outputs on toy 8-bit
designs.

## Labels

* **MEASURED**: simulated here, exhaustively, on the netlist named.
* **RECORDED**: a value already stored in the repository, shown for comparison, not re-run.
* **UNTESTED-HERE**: needs Yosys (or z3), which this machine does not have. `cloud/run_cloud.sh` produces it.
* **ASSUMED**: a modelling choice or weight, stated where used.

Machine for every MEASURED number: 2 CPUs, Python 3, numpy; no Yosys, no z3.

### Design-level search (reference gate mappings written by this tool)

| design | goal | best fix found | min flips before | min flips after | cost |
|---|---|---|---|---|---|
| V0 | >= 2 | 8-bit sparse state, 2 owning copies, no voter | 1 | 2 | +50 gates, +6 flops |
| V0 | >= 3 | 8-bit sparse state, 3 owning copies, armed 0xC8 | 1 | 3 | +61 gates, +6 flops |
| V1 | >= 2 | voter removed: each state bit owned by one of the 2 copies | 1 | 2 | +1 gate |
| V1 | >= 3 | 3 owning copies, armed 0xCC -> 0xC8 | 1 | 3 | +12 gates |
| V2 | >= 3 | armed 0xCC -> 0xC8 | 2 | 3 | -1 gate |
| V2 | >= 4 | 4 owning copies, ownership 32103210, idle 0x61, armed 0x49 | 2 | 4 | +13 gates |
| V2 | >= 5 | not reached (closest: 5 copies, 4 flips) | 2 | - | - |

"Before/after" = smallest minimum over the three unmerged mappings, any number of cycles. Decision latency is
unchanged (2 cycles) in every fix. For V0 the fix changes what `boot_word` shows before the decision (F0/C8, or
F0/CC for goal 2, instead of 69, because `boot_word` is now the state word rather than the decoded output); a
consumer that tests `== 0x96` is unaffected. Cost = gates and flops of the select-shared mapping; ranking uses gates + 6 x flops
(ASSUMED weight). Every fix drops back to 1 flip if synthesis merges the identical copies; that is why each fix comes
with the separation script.

## Commands

```
export GLITCHSAT_ROOT=/path/to/glitchsat                       # needed for the lint, the tests and the z3 check
./glitchsat harden design v2 --goal 3 --out fixes/             # search; writes .v, .ys, netlists, evidence + panel JSON
./glitchsat harden design --spec my.json --goal 3 --allow encoding,ownership
./glitchsat harden netlist nl.json --top v2 --goal 2 --groups "0,3,6;1,4,7;2,5" [--mask 0x0F] --out fixed/
./glitchsat harden check nl.json --top v2 --kmax 3 --cycles all
./glitchsat harden moves v2                                    # what each change alone buys
./glitchsat harden resynth --specs results/designs --out out/  # needs Yosys (see below)
```

`design` exit code: 0 goal reached, 1 not reached, 3 bad input.

Files written by `design --out DIR` for the best fix:

| file | content |
|---|---|
| `<d>_g<G>.v` | hardened Verilog (module `<d>h`) |
| `<d>_g<G>.ys` | Yosys script: project plain flow + copy-separation guard |
| `<d>_g<G>_{select-shared,mux-shared,unshared}.json` | the reference netlists that were verified (readable by `scripts/glitchsat.py`) |
| `<d>_g<G>_netlist.v` | the select-shared netlist as structural Verilog |
| `<d>_g<G>.spec.json` | before/after description (input to `resynth`) |
| `<d>_g<G>.evidence.json` | every number, witness attacks, cost, labels |
| `<d>_g<G>.suggest_fix.json` | Studio panel card |

The combined panel file for all results is `studio/suggest_fix.json` (schema `glitchsat-studio-suggest-fix/1`): one card
per design and goal with before/after, plain-language steps, per-mapping evidence, cost, files, plus the
netlist-level fixes and the stored-netlist confirmations.

## Re-synthesis check (cloud VM, Ubuntu 24.04, apt Yosys 0.33)

```
GLITCHSAT_ROOT=/path/to/glitchsat sh cloud/run_cloud.sh          # full grid
QUICK=1 GLITCHSAT_ROOT=/path/to/glitchsat sh cloud/run_cloud.sh  # 16 configurations per design, minutes
```

It installs Yosys, numpy, z3-solver and pytest, runs the tests, calibrates against a recorded value (repository V2,
plain flow, must give 2 flips), then synthesises the before design (repository RTL and this tool's description) and
every fix with the 96 configurations of `research/c2/e2_variance` x guard off/on, and re-verifies every netlist
exhaustively. Per row: gates, flops, number of distinct match nets (1 = copies merged), min flips, witness, whether the
goal is met. Rows are cached by a hash of script, Verilog, Yosys version and options (`--no-cache` to redo) and run in
parallel (`WORKERS`). With z3 the plain-flow netlists are also checked by `scripts/glitchsat.py check` (6 cycles) and
compared with the simulator. Output: `cloud_out/resynth_summary.md`, `resynth_rows.csv`, `env.txt`,
`calibration.txt`, and a tarball.

Status here: the scripts are written and the dry run writes all 3456 scripts; the pipeline (synthesis call,
verification, match-net count, cache) is tested with a stand-in that returns reference netlists. Real Yosys runs and
the z3 cross-check: **UNTESTED-HERE**. Whether the `keep` guard stops `opt_merge` from folding the copies is the first
thing that run answers; it is read from the Yosys source, not measured.

## Tests

```
python3 -m pytest -q tests          # about 30 s; GLITCHSAT_SLOW=1 adds the long exhaustive cases
```

## Layout

`harden/sim.py` exhaustive bit-parallel fault simulator; `netlist.py` Yosys JSON reader/writer; `spec.py` design
description, gate mappings, Verilog and Yosys script writers; `search.py` moves, predictor, search; `unmerge.py`
single-point removal; `report.py` evidence, tables, panel JSON; `resynth.py` re-synthesis grid; `cli.py` commands.
The repository is only read, never modified.
